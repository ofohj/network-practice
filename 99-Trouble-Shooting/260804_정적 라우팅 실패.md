## 3. 파악된 원인: 라우터 0의 포트 설정 오류
- 아래 명령어를 라우터0의 CLI 창에 재입력

```bash
enable
configure terminal

interface gigabitEthernet 0/0/0
 ip address 192.168.10.1 255.255.255.0
 no shutdown
exit
```

- 이후, 핑 테스트 다시 시도
  - `ping 192.168.10.1` (패킷이 내 게이트웨이까지 가는가?) → 성공
  - `ping 10.10.10.1` (내 라우터 건너편 포트까지 가는가?(Router0 WAN 포트)) → 성공
  - `ping 10.10.10.2` (상대방 라우터 포트까지 가는가?(Router1 WAN 포트)) → 성공
  - `192.168.20.10` (상대방 PC까지 가는가?(최종 목적지 PC1)) → **실패**

---

## 4. 현재까지 상황
- 라우터0과 1 사이의 물리적인 연결 및 정적 라우팅까지는 성공
- PC0에서 보낸 패킷이 상대편 라우터까지 도착은 했으나, 지사 구간에서 PC1로 전달되지 못하는 상태

## 5. 시도한 해결방안 2
### 1) 라우터 1의 포트 설정 오류(앞선 해결책과 동일한 방법)
- 아래 명령어를 라우터1의 CLI 창에 재입력
  
```bash
enable
configure terminal
interface gigabitEthernet 0/0/0
 ip address 192.168.20.1 255.255.255.0
 no shutdown
exit
```

- 이후, PC1에서 핑 테스트 다시 시도
  - `ping 192.168.20.1` (내 라우터 게이트웨이로 패킷이 잘 가는가?) → 성공
  - `ping 192.168.10.10` (본사 PC0으로 가는가?) → 성공

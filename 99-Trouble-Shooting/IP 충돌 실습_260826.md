실수로 서로 다른 PC에 동일한 IP를 할당해버렸을 경우, 어떻게 충돌나는지 궁금해져서
IP 충돌 실습을 해보려고 한다.

# 주제: IP 충돌이 났을 경우 통신 상태 확인하기

## 🌐 학습 목표
- 동일한 IP 주소를 사용하는 두 장비가 동일한 브로드캐스트 도메인에 존재할 때 발생하는 통신 장애 매커니즘을 이해한다.

---

## 🌐 실습순서
## 1. 토폴로지 구성하기
- 스위치 1대
- PC0: 192.168.10.10 /24
- PC1: 192.168.10.10 /24
- PC2: 192.168.10.30 /24

<img width="520" height="379" alt="스크린샷 2026-08-26 233206" src="https://github.com/user-attachments/assets/3b7fefb7-0d8d-4521-9e3b-c878ea3bd62c" />

### ⚠️ 주의할 점
- Cisco Packet Tracer에서 같은 브로드캐스트 범위 안에 있는 PC들에 동일한 IP를 할당하면 `This address is already used in the network` 경고문이 뜨고 입력이 차단된다.
  
  <img width="657" height="85" alt="스크린샷 2026-08-26 233000" src="https://github.com/user-attachments/assets/6ba4e75c-74f3-4a83-8dbc-628526037e83" />

- 이를 우회하기 위해 PC0에서 스위치까지 연결된 케이블을 끊고, PC0에 IP 할당을 먼저 해준 후, 다시 케이블로 연결한다.

---

## 2. PC0, 1에서 2로 핑 테스트
- PC0, PC1의 cmd창에서 `ping 192.168.10.30`을 입력해 PC2로 핑 테스트를 보냈다.
- **예상:** PC0, 1에서 2로 갈땐 문제없지만 PC2에서 다시 응답을 보낼 때 동일한 IP를 가진 장비가 2대라 통신이 실패할 줄 알았음

- **결과:** 먼저 핑 테스트를 진행한(먼저 패킷을 보낸) PC와 통신에 성공함
  
  <img width="1877" height="723" alt="image" src="https://github.com/user-attachments/assets/18c222ee-f0c1-4ee7-bb9b-d5eac7fbeb7f" />

- **원인:**
  - PC가 패킷을 송신하는 순간, 스위치가 해당 포트로 들어온 프레임의 출발지 MAC 주소를 읽어서 MAC 주소 테이블에 등록함
  - 이후, PC는 ARP를 통해 IP와 MAC 주소를 1:1로 짝지어서 기억하게 됨
  - 즉, PC2의 ARP 테이블에 `192.168.10.10 = PC1의 MAC 주소`가 이미 고정(캐싱)되어있고, 스위치의 MAC 주소 테이블에도 동일하게 매핑되어 있기 때문에 먼저 패킷를 보낸 PC만 통신에 성공하게 됨

---

## 3. PC2에서 0, 1로 핑 테스트
- PC2의 cmd창에서 `ping 192.168.10.10`을 입력해 동일한 IP를 가진 PC들로 핑 테스트를 보냈다.
- 결과: 이것 또한 마찬가지로, 먼저 패킷을 보낸 PC와 통신이 성공했다.

---
## 🌐 배운 점
- 특정 IP 주소를 이미 사용했다는 걸 까먹고 다른 PC에 동일한 IP를 할당하는 실수를 할 수도 있지 않을까 싶었는데, 시스코 패킷 트레이서는 중복 IP 입력 시 에러 메시지 띄워 실수를 자동 차단해 준다.
  (하지만 실제 PC에서는 이러한 기능이 없을 수 있으므로, IP 할당 시 주의해야 한다!!!)
- 그럼에도 불구하고 동일한 네트워크 상에서 IP를 중복해서 사용했다하더라도, **L2 환경에서는 IP뿐만 아니라 MAC 주소와 ARP 테이블을 기반으로 통신하므로**, 선점된 장비가 일부 통신을 유지하기도 한다.
  (통신이 유지되더라도 IP가 중복 설정된 것은 보안 사고이며 추후 장애로 이어질 수 있으므로, IP 할당 시 주의해야 한다!!!)

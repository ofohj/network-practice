# 주제: Access 포트에 할당된 VLAN 번호 불일치로 인한 통신 불가

## 🌐 학습 목표
- 스위치 간 VLAN 설정이 맞지 않을 때 L2 패킷이 **어느 지점**에서 **왜** 드랍되는지 시뮬레이션 모드로 확인하기

---

## 🌐 실습 순서
## 1. 토폴로지 구성

- 각 PC의 IP 대역은 동일하게 설정(192.168.10.0/24)
- PC0: 192.168.10.10/24
- PC1: 192.168.10.20/24

## 2. 문제 상황 세팅하기
- PC0과 PC1은 같은 IP 대역에 있지만, 두 스위치의 포트에 서로 다른 VLAN을 할당하여 통신이 막히도록 만들기
- 각 스위치의 이름이 헷갈리지 않도록 SW1, SW2라고 이름 붙이기

- SW1 CLI
  ```bash
  enable
  conf t

  vlan 10
  exit

  interface fastEthernet 0/1
  switchport mode access
  switchport access vlan 10
  exit
  ```

- SW2 CLI
  ```bash
  enable
  conf t

  vlan 20
  exit

  interface fastEthernet 0/1
  switchport mode access
  switchport access vlan 20
  exit
  ```
  
---

(4) Capture/Forward(▶|) 버튼을 누르면서 패킷 추적하기

(5) 결과 확인하기(아래)
  
  <img width="1163" height="680" alt="스크린샷 2026-08-31 223524" src="https://github.com/user-attachments/assets/1873751c-df63-4ac5-be79-8f3b3e0f8f2b" />

  - ⚠️ 의도하던 결과가 나오지 않고 `The ARP request times out. The ARP process drops this buffered packet.` 경고창이 떴다.
  - ⚠️ 원인:
    1) PC0은 PC1의 MAC 주소를 모르기 때문에 PC1 쪽으로 ARP Request를 보냈음
    2) 하지만 SW1과 SW2의 VLAN 번호가 달라서 이 ARP 패킷이 PC1까지 가지 못했음
    3) 그 결과, 응답을 못 받은 PC0은 타임아웃을 띄우고 패킷을 폐기(X표시) 함

### 2) 문제 해결하기
- 패킷이 PC0 -> SW1 -> SW2까지는 가야함
- 초반에 VLAN만 설정해주고 Trunk 설정을 해주지 않은 것이 주된 원인.
(1) 스위치 간 연결해주기(Trunk)
  - SW1, SW2 CLI에 동일하게 적용
    ```bash
    enable
    conf t
    interface fastEthernet 0/24
    switchport mode trunk
    ```

### 3) 통신 리셋 후 핑 보내기
(1) 시뮬레이션 창에서 `Reset Simulation` 클릭

(2) PC0의 CMD 창에서 `arp -d` 입력 후 `ping 192.168.10.20` 재입력

(3) Capture/Forward(▶|) 버튼을 누르면서 패킷 추적하기

## 💡 추가로 궁금했던 내용
### Q. VLAN 설정할 때 switchport mode를 access로 설정했는데, 다른 모드는 뭐가 있는지?
- Access mode
  - 단 하나의 VLAN 트래픽만 다니는 포트
  - PC, 프린터, 서버같은 호스트 디바이스를 스위치에 연결할 때 사용
  - ⚠️ 그래서 나는 PC0-SW1을 연결할 때 이걸 입력함!

- Trunk mode
  - 여러개의 VLAN 트래픽이 하나의 랜선을 공유해서 다니는 포트
  - **각자 다른 VLAN 포트에 연결된** 스위치-스위치, 스위치-라우터 연결에 사용(VLAN 태그를 붙여서 전송)
    > 같은 VLAN 포트에 연결됐다면 Trunk를 설정할 필요가 X !!
  - ⚠️ 이걸 입력을 안해줘서 오류가 났고, 이후 SW1-SW2를 연결할 때 입력해줌!

- Dynamic mode
  - 상대방 장비와 DTP(Dynamic Trunking Protocol) 협상을 거쳐, 스스로 Access가 될지 Trunk가 될지 자동으로 결정하는 모드

---
## ▶️ 총정리
- 서로 다른 VLAN에 속한 스위치를 연결할 때는 Trunk를 설정해야한다.
- 서로 다른 VLAN에 속한 PC는 L2 스위치만으로 통신할 수 없다 (L3 라우팅 필요).
- 다른 VLAN의 PC로 통신을 시도하면 패킷이 건너편 스위치까지는 가더라도 목적지 포트의 VLAN이 달라 스위치 내부에서 폐기된다.

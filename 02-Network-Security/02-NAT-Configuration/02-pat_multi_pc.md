## ★ PAT의 편리함: 만약 Static NAT으로 설정했다면?
### 1) 필요한 공인 IP 개수의 증가
- PAT은 공인 IP 1개로 PC 여러 대를 처리했음
- Static NAT는 1:1 방식이므로, PC 3대가 있을 경우 공인 IP도 최소 3개가 필요함

### 2) 라우터 설정의 번거로움 증가
- PAT는 명령어를 한번 입력해두면, 새로운 PC가 추가되어도 자동으로 공인IP와 포트번호가 할당됨
- NAT 설정 시, PC마다 매핑 명령어를 일일이 등록해야 함
  ```bash
  Router0(config)# ip nat inside source static 192.168.10.10 200.1.1.1
  Router0(config)# ip nat inside source static 192.168.10.20 200.1.1.2
  Router0(config)# ip nat inside source static 192.168.10.30 200.1.1.3
  ```

## ★ 그럼에도 불구하고 NAT을 사용하는 경우와 그 이유

### 1) 외부에서 내부로의 상시 접속이 필요할 때
- **PAT의 한계:** PAT는 내부에서 외부로 나가는 통신을 기본 전제로 동작한다. 만약 외부의 누군가가 사전 연결 없이 내부망에 접속하려고 하면, 라우터는 이 요청을 내부의 어떤 PC로 전달해야 할지 PAT가 할당하는 포트 정보만으로는 알 수 없다.
- **NAT의 필요성:** 외부 웹 서버, 메일 서버, VPN 장비 등 외부 사용자가 24시간 언제든 지정된 고정 IP로 찾아와야 하는 서버에서는 NAT가 필수적이다.

### 2) 포트 번호 변경이 불가능한 호스트 및 애플리케이션을 지원할 때
- **PAT의 한계:** PAT는 TCP/UDP 포트 번호를 임의로 변환하며 통신한다. 하지만 일부 옛날 프로토콜이나 특수한 보안 통신은 패킷 내 포트번호가 바뀌면 패킷이 변조되었다고 생각해 통신을 차단해 버린다.
- **NAT의 필요성:** 이 때, IP 주소를 정확하게 바꿔주는 NAT를 사용하여 안정적인 통신을 할 수 있다.

### 3) 기업 간 망 연동 시 IP 대역 충돌 해결
- 두 기업이 합병되거나 B2B 회선을 연결할 때 양사 내부망이 같은 사설 IP 대역을 사용하고 있다면 IP 충돌이 발생한다.
- 이 때 양측 라우터에 NAT를 설정해 대역 전체를 중계용 IP로 바꿔주면 기존 내부 IP를 바꿀 필요 없이 충돌을 해결할 수 있다.

## ★ 대체 기술들
### 1) IPv6(근본적인 해결책!)
- 주소 체계를 128비트로 확장했기 때문에 사실상 무한대에 가까운 공인 IP를 제공할 수 있음
- 모든 내부 기기에 서로 다른 글로벌 공인 IP를 부여할 수 있으므로, NAT이나 PAT 기술을 적용할 필요가 없어짐

### 2) 포트 포워딩
- NAT처럼 공인 IP를 다 사지 않고, 공인 IP의 특정 포트만 내부 서버 IP의 포트로 넘겨주는 기술
- 장점: 공인 IP 1개로 웹 서버, 메일 서버 등을 포트별로 나누어 외부로 공개할 수 있어 소규모 기업 및 가정에서 NAT 대용으로 쓰임

### 2) 리버스 프록시
- 내부 서버가 외부로 먼저 암호화 터널을 뚫어두고, 외부 사용자는 그 터널을 통해 들어옴

  → 우리가 네이버나 구글을 사용할 수 있는 이유
- 라우터에 공인 IP를 매핑하거나 포트포워딩을 할 필가 없어 보안상 훨씬 안전해짐
